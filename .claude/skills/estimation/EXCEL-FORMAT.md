# Estimation workbook format (v6.1, schemaVersion 3)

Generated by `scripts/build_workbook.py`. Exactly five sheets, in this order.
Tasks holds the only typed hours. Every other number is a live formula, so
editing a task updates every total. Input cells are blue bold text on a yellow
fill, headers are white bold on blue (`4472C4`), helper columns use a grey
header, hours use `0.0`, dates `yyyy-mm-dd`. No margin, markup or buffer cell
exists anywhere.

Ranges are bounded to the data rows (`Tasks!$E$2:$E$<n+1>`). Insert new rows
inside the table, not below it, so Excel extends every range.

## Committed and Tentative (the exact definition)

This is the same definition the workscope checker uses, so both numbers agree:

- **Committed hours** = sum of task `minHours` over Included features in Committed milestones, plus SHARED tasks in Committed milestones.
- **Tentative hours** = sum of task `minHours` over Included features in Tentative milestones, plus SHARED tasks in Tentative milestones. Shown per release.
- **Upper range** of either = the same task set, summing `maxHours` where given, else `minHours`.
- A blank `minHours` adds nothing and is counted as Unestimated, never as zero effort.
- A milestone with no `commitment` is Committed, one with no `release` is "Full scope".
- Tentative hours are never added into the committed number. The only combined figure is the column labelled "Committed + tentative (not a commitment)".
- Pending (proposed), Deferred (not planned in any phase) and Excluded features are in neither, whatever their milestone.

In the workbook: `SUMIFS(Tasks!E, Tasks!I, "Included", Tasks!K, "Committed")`
(Tasks!I is the scope helper, `Included` for SHARED, Tasks!K the milestone's
commitment), and the same with `"Tentative"`, plus `Tasks!J = <release>` per release.

## 1. Summary

| Block | Content |
|---|---|
| Header (rows 1 to 7) | Project, Client, Prepared by, Date, **Hours per day** (input `B5`), the "no margin, no markup, no buffer" note, **Scope case** (`project.scopeCase`: A full quote, B client-defined MVP, C MVP-first default, or "Not recorded") |
| Releases and milestones | One row per milestone in JSON order: ID, Name, Release (input), Commitment (input), effective Release `IF(input="","Full scope",input)`, effective Commitment `IF(input="","Committed",input)`. Tasks and Features look these up. |
| Effort by role and milestone | Two label rows above the header give each milestone column's Release and Commitment (live). Milestone columns are ordered committed first, then tentative, grouped by release. Rows: UI/UX, Frontend, Backend, AI, Mobile, DevOps, QA, PM, each `otherRoles` entry, Total. Milestone cell: `SUMIFS(Tasks!E, Tasks!B, "<milestone>", Tasks!D, <key>, Tasks!I, "Included")`. Then **Committed subtotal**, **Tentative subtotal**, **Committed + tentative (not a commitment)** (each an independent `SUMIFS`), and Committed Person-Days = committed / `$B$5`. |
| Scope buckets | Columns Bucket, Hours, Person-Days, Upper Range, Note. **Committed (<release names>)**. One **Future phase (tentative): <release>** row per tentative release, with hours, person-days and upper range. **Future phases total (tentative, not a commitment)**. Proposed: Pending features. Proposed: recommended items with effort (`SUM(Recommended!G)`). Proposed total. Deferred (not planned in any phase). Excluded. Unestimated tasks (`COUNTBLANK(Tasks!E)`, a count). Features with no tasks (a count). Upper range (not committed), committed scope only. |
| Feature counts | `COUNTIF` of each priority P0 to P3 and each recommendation |
| Feature dependencies | One row per feature with `dependsOn`: `IF(AND(<each dependency's scope status>="Included"),"Resolved","Unresolved")`, a missing ID reads as Missing. Count of unresolved features. |
| Provisional milestone ETA | Label "Provisional: roles in parallel within a milestone, milestones in sequence, committed milestones first and tentative milestones after". With `schedule`: Start date and people per role (inputs), per milestone (committed first) Working Days = `ROUNDUP(MAX(0, IF(people>0, hours/(people*$B$5), 0), ...), 0)`, Start = `WORKDAY(start-1, 1)` then `WORKDAY(previous end, 1)`, End = `IF(days=0, start, WORKDAY(start, days-1))`, Staffing Gaps, Commitment. Then **Committed delivery date (provisional)** and **Tentative phases end (provisional, not a commitment)**. Without `schedule`: every ETA cell reads "Pending scheduling inputs". |

## 2. Features

Columns: ID, Name, Description, Source, Priority, Recommendation, Reasoning,
Milestone, Scope Status, **Release** and **Commitment** (`INDEX/MATCH` lookups
from the milestone table, "Unknown milestone" when the ID is not defined),
**Scope Decision** (typed `scopeDecision` from the scope strategy card, optional),
one hours column per role (fixed order, then other roles), Total Hours,
Person-Days, Depends On, Estimate Status, Calendar ETA.

- Role cell: `SUMIFS(Tasks!E, Tasks!A, $A<row>, Tasks!D, "<key>")`, all scope statuses shown.
- Total Hours: `SUM` of the role cells. Person-Days: total / `Summary!$B$5`.
- Calendar ETA: always "Pending scheduling inputs" at feature level.
- SHARED work does not appear here. It shows on the Summary only.

## 3. Tasks

| Col | Field | Notes |
|---|---|---|
| A | Feature ID | Feature ID or `SHARED` |
| B | Milestone | Feature task: `INDEX/MATCH` of the feature's milestone. SHARED: typed. |
| C | Task | |
| D | Role | Role key |
| E | Min Hours | Input. Blank means Unestimated. |
| F | Max Hours | Input, optional |
| G | Confidence | High, Medium, Low |
| H | Assumption | |
| I | Scope Status (formula) | `Included` for SHARED, else the feature's scope status, else "Unknown feature" |
| J | Release (formula) | The milestone's effective release |
| K | Commitment (formula) | The milestone's effective commitment |

## 4. Recommended

Columns: ID, Feature, Category, Problem, Priority, Release, Effort Hours,
Depends On, Risk If Omitted, Rationale, Approval, Included in Estimate (always
"No"). A note under the table says inclusion means adding the item as a feature
(source Recommended) with tasks.

## 5. Validation

Columns: #, Check, Result, Detail (a live explanation with the numbers). Result
is coloured by conditional formatting. A math mismatch is FAIL, a missing input
is REVIEW. An Overall row is FAIL if any FAIL, else REVIEW if any REVIEW, else PASS.

| # | Check | PASS when |
|---|---|---|
| 1 | UI/UX hours reconcile across Tasks, Features, Summary | Tasks UIUX Included = Features UIUX (Included) + SHARED UIUX = Summary UI/UX combined column |
| 2 | Feature role hours reconcile with Tasks | Sum of all Features role cells = Tasks hours where Feature is not SHARED |
| 3 | Feature total equals the sum of its role columns | No row where Total differs from the role sum |
| 4 | Milestone totals equal project totals (each role) | Each role row and the Total row: milestone cells sum to the combined column, committed milestone cells to the Committed subtotal, tentative ones to the Tentative subtotal |
| 5 | ETA is not inferred from total effort alone | ETA is Pending (every ETA cell says so), or the per-role method is used. REVIEW on a staffing gap. |
| 6 | Every included feature has a priority | Included count = Included with P0 to P3, else REVIEW |
| 7 | Excluded and deferred features are absent from committed hours | Committed + tentative = all task hours minus Deferred, Excluded and Pending |
| 8 | Recommended items are not in committed hours | Committed = raw Included + Committed task hours, combined = Included task hours, every register row says No |
| 9 | No task counted twice | No duplicate Feature + Task + Role (`SUMPRODUCT(--(COUNTIFS(...)>1))`) |
| 10 | No margin or markup | Committed and feature totals equal the raw sums of typed task hours |
| 11 | Unknown estimates are not treated as zero | No blank Min Hours, else REVIEW |
| 12 | Every task role is known and every task feature exists | No unknown role keys and no task referencing a missing feature |
| 13 | Tentative hours are absent from the committed total | Committed and Tentative totals equal an independent `SUMPRODUCT` recomputation (scope Included x milestone commitment looked up with `COUNTIFS`), Committed equals the sum of committed milestone columns only, and no Included feature with Scope Decision `Tentative` sits in a Committed milestone. FAIL otherwise. |
| 14 | Every committed feature is P0 or P1, or explains why | No Included feature in a Committed milestone that is not P0 or P1 and has a blank Reasoning, else REVIEW |
| 15 | Every milestone has a release and a commitment | No blank Release or Commitment input and every effective commitment is Committed or Tentative, else REVIEW (a defaulted v6.0 file shows REVIEW here) |

## Verification

`build_workbook.py` evaluates every formula with `scripts/formula_eval.py` and
compares the results with a recomputation from the JSON (committed, tentative per
release, upper ranges, the role grid, ETA dates, all 15 checks), fails on any
error value, and fails on any formula outside Tasks that multiplies by a numeric
literal. `--selftest` builds both bundled examples plus five negative cases:
duplicate task (check 9 FAIL), unknown role and feature (check 12 FAIL), a
tentative feature placed in a committed milestone (check 13 FAIL), a committed P3
feature with no reasoning (check 14 REVIEW), milestones without release fields
(check 15 REVIEW). Final check: recalculate in Excel or LibreOffice before sharing.
