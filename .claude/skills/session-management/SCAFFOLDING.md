## Post-Scaffold: Project Structure Conventions

> [!CRITICAL]
> Ask the user which structure their project uses BEFORE scaffolding. Do not assume.

**Ask user:**
> "How is your project organized?
> 1. **Monorepo** — frontend + backend + mobile all in one repo
> 2. **Multi-repo** — separate repos for frontend, backend, mobile
> 3. **Single app** — only one app (e.g., just a backend API, or just a frontend)"

---

### Option 1: Monorepo (all apps in one repo)
```
[project-root]/
├── apps/
│   ├── web/          <- Next.js or Vite frontend (from CLI)
│   ├── api/          <- NestJS or Express backend (from CLI)
│   └── mobile/       <- Expo or RN project (from CLI)
├── AI_DOCS/          <- Generated by skills
├── .claude/          <- Framework (gitignored)
├── CLAUDE.md         <- Generated by claude-md skill
└── .gitignore
```

### Option 2: Multi-repo (separate repos)
Each repo gets its own `.claude/` folder and `AI_DOCS/`:
```
# Repo 1: frontend
web-app/
├── src/
├── AI_DOCS/          <- Frontend-specific docs
├── .claude/          <- Framework copy
└── CLAUDE.md

# Repo 2: backend
api-server/
├── src/
├── AI_DOCS/          <- Backend-specific docs
├── .claude/          <- Framework copy
└── CLAUDE.md

# Repo 3: mobile (if applicable)
mobile-app/
├── src/
├── AI_DOCS/          <- Mobile-specific docs
├── .claude/          <- Framework copy
└── CLAUDE.md
```

> For multi-repo: the `api-contract.md` must be kept in sync across repos. Store the master copy in the backend repo and share it.

### Option 3: Single app
The CLI output IS the project root. No extra nesting:
```
[project-root]/
├── src/              <- CLI-generated source
├── AI_DOCS/
├── .claude/
├── CLAUDE.md
└── .gitignore
```

## MCP Server Configuration

> [!IMPORTANT]
> Governed by `.claude/rules/mcp-rules.md`. Free (Enforced) servers are written automatically; credentialed (Gated) servers are offered and require approval. Delegate to `mcp-connector` (SK-023).

**Process** (mcp-rules.md Rule 4):
1. Read the confirmed stack from `AI_DOCS/memory/stack.md`
2. Cross-reference with `mcp-connector/templates/mcp-server-recommendations.md`
3. Write matched **Enforced (free)** servers to project-root `.mcp.json` (no prompt)
4. Offer matched **Gated (credentialed)** servers; wire approved ones with `${ENV_VAR}` references (never literals)
5. Wire to the dev environment + port (mcp-rules.md Rule 6b); record the active set in `stack.md` → `## MCP Servers`

**Quick Mapping**:
| If stack includes | Server | Tier |
|-------------------|--------|------|
| (any project) | fetch, sequential-thinking, context7 | Enforced |
| (any web frontend) | playwright | Enforced |
| Next.js | next-devtools-mcp | Enforced |
| Shadcn/ui | shadcn | Enforced |
| MUI | @mui/mcp | Enforced |
| Prisma | prisma mcp | Enforced |
| PostgreSQL | postgres-mcp | Gated |
| MongoDB | mongodb-mcp-server | Gated |
| Supabase | @supabase/mcp-server-supabase | Gated |
| Payments | @stripe/mcp | Gated |
| Maps/Location | gmp-code-assist | Gated |

**See**: `mcp-connector/templates/mcp-server-recommendations.md` for full catalog, `.mcp.json` template, and setup instructions.

## Git Repository Initialization (NEW PROJECT ONLY)

> [!CRITICAL]
> A project without a proper Git structure will fail at the first milestone transition.
> This step runs ONCE during Workflow A and sets up the entire branching model.

Ask user:
> "Do you want me to initialize the Git repository and set up the branching structure?
> - **YES** — I will run git init and create: main, develop, milestone-1 branches
> - **NO** — I will provide the commands for you to run manually"

**If YES**, execute (or show) these commands:
```bash
git init
git add .gitignore    # create if not present (see template below)
git commit -m "chore: initial project scaffold"
git branch -M main
git checkout -b develop
git checkout -b milestone-1
git checkout develop
echo "Git structure initialized: main -> develop -> milestone-1"
```

**Default `.gitignore` additions** (append to existing):
```
# Claude Code — skills NOT committed, rules + settings ARE committed
.claude/skills/
.claude/settings.local.json

# Environment files (never commit secrets)
.env
.env.local
.env.staging
.env.production
*.env

# AI generated runtime (commit AI_DOCS/ intentionally, not via add -A)
AI_DOCS/memory/*.tmp

# Per-project scratch: gitignored working directory for framework scripts
# (unpacked XML trees, intermediate PDFs/images, generated helper scripts).
# Safe to delete. Never a source of truth.
AI_DOCS/.temp/

# Test/coverage/E2E raw output — temp data, never pushed. ALL runners write here
# (routed via the vitest/jest/playwright configs); the validated verdict JSON in
# AI_DOCS/quality/mavs/ stays tracked as evidence.
AI_DOCS/quality/test-artifacts/
tests/e2e/.auth/
# Belt-and-suspenders: if any runner ever writes to the project root, ignore it too.
coverage/
playwright-report/
test-results/
```

Write to `AI_DOCS/memory/project-context.md` under `## Git State`:
```
## Git State
- Production Branch: main
- Integration Branch: develop
- Current Milestone Branch: milestone-1
- Active Feature Branches: none
- Last Merged: (none)
- Last Tag: (none)
```

Reference: [github-ops](../github-ops/SKILL.md) for full branching protocol.
