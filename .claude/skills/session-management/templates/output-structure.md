# Output Structure Guide

> **Purpose**: Define the standardized folder structure for all AI-generated outputs  
> **Audience**: All AI skills

---

## Overview

All AI-generated outputs are consolidated in a centralized location for automation, traceability, and developer handoff.

---

## Standard Output Structure

```
project-root/
├── .claude/                    # Claude Code configuration
│   ├── settings.json           # Permissions, hooks, auto-formatting (committed to git)
│   ├── settings.local.json     # Personal overrides (gitignored)
│   ├── rules/                  # Per-directory enforcement rules
│   │   ├── development-rules.md    # Spec-first, architecture, naming (all code files)
│   │   ├── security-rules.md       # OWASP Top 10, auth, secrets (all code files)
│   │   ├── api-rules.md            # Contract-first API development (backend files)
│   │   ├── frontend-rules.md       # Responsive, accessibility (frontend files)
│   │   ├── component-reuse-rules.md # Registry check, design tokens (component files)
│   │   ├── testing-rules.md        # Traceability, coverage (test files)
│   │   └── mobile-rules.md         # Platform handling, performance (mobile files)
│   └── skills/                 # Skills framework (40+ SDLC skills)
│       ├── REGISTRY.md         # Central skill catalog
│       ├── session-management/ # Entry point skill
│       ├── workscope/          # Scope discovery
│       ├── design-system/      # UI/UX design
│       ├── build/ # Implementation
│       ├── qa-testing/         # Quality assurance
│       └── ...                 # 40+ skills total
├── AI_DOCS/                    # All AI-generated outputs
├── CLAUDE.md                   # Session context file (generated by claude-md skill)
└── code/                       # Implementation code (or apps/ for multi-app)
```

### Claude Code Feature Map

| Feature | Location | Purpose | Shared? |
|---------|----------|---------|---------|
| **Settings** | `.claude/settings.json` | Permissions, hooks, excluded files | Yes (git) |
| **Local settings** | `.claude/settings.local.json` | Personal overrides | No (gitignored) |
| **Rules** | `.claude/rules/*.md` | Per-directory enforcement (path-based) | Yes (git) |
| **Skills** | `.claude/skills/*/SKILL.md` | Full SDLC skills framework | Yes (git) |
| **CLAUDE.md** | `CLAUDE.md` (root) | Session context, project state | Yes (git) |

### Hooks (in settings.json)

| Hook | Event | Behavior |
|------|-------|----------|
| `PreToolUse` | Before file edits | Blocks edits to locked api-contract.md |
| `PostToolUse` | After code edits | Auto-runs Prettier + ESLint |
| `Stop` | Session ending | Verifies memory files are updated |
| `SessionStart` | Session starting | Loads task.md and gate-status.md |

## AI_DOCS Structure

### 1. Memory Files (Created on Demand)

> **Pattern**: Skills copy templates from `session-management/templates/` if not present.

| Memory File | Source Template | Purpose |
|-------------|-----------------|---------|
| `AI_DOCS/memory/status.md` | `status-template.md` | Short-term state & decisions |
| `AI_DOCS/memory/task.md` | `task-execution-template.md` | Execution checklist |
| `AI_DOCS/memory/implementation-plan.md` | `implementation-plan-template.md` | Context memory |
| `AI_DOCS/memory/context-map.md` | (created inline) | Entities, FRD refs |
| `AI_DOCS/memory/reviews.md` | (created inline) | VRB audit logs |

**Runtime Copy Pattern**:
```
1. Skill checks: Does AI_DOCS/memory/[file].md exist?
2. If NO: Copy from session-management/templates/[template].md
3. If YES: Read and continue
```

## Code Structure

> Ask user which structure they use. See `session-management/SKILL.md` Step 1.6 for the full question.

### Option A: Monorepo (All apps in one repo)

```
apps/
├── web/                        # Frontend (Next.js, Vite)
├── api/                        # Backend (NestJS, Express)
└── mobile/                     # Mobile (Expo, React Native)
```

### Option B: Multi-Repo (Separate repos per app)

Each repo has its own `AI_DOCS/`, `.claude/`, and `CLAUDE.md`.
The `api-contract.md` master lives in the backend repo and is shared.

### Option C: Single App

```
code/
├── backend/                    # Single backend
└── frontend/                   # Single frontend
```

## Shadow Mirror Rule

| Location | Purpose | Status |
|----------|---------|--------|
| `AI_DOCS/design/src/` | Design staging | READ-ONLY Reference |
| `apps/` or `src/` | Production code (per project structure) | LIVE PROD CODE |

**Golden Rule**: `code/` is the source of truth. Never overwrite without manual merge.
