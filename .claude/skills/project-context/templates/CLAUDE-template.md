## Critical Rules (ALWAYS FOLLOW)

> Full rules in `.claude/rules/`. Below are the top rules that MUST be followed in every response.

### Before Writing ANY Code
1. Read `AI_DOCS/architecture/api-contract.md` before any API call — match exact URL, method, body, response
2. Read `AI_DOCS/design/component-registry.md` before any UI — if component exists, USE IT, never recreate
3. Read `AI_DOCS/design/design-dna.md` before any styling — use only defined colors, spacing, fonts
4. Every code change must trace to `AI_DOCS/planning/tech-spec.md` — no ghost features

### Code Standards (BLOCKING)
5. No `any` type in TypeScript — use proper types
6. No `console.log` in production — use structured logger
7. No hardcoded colors/spacing — use design tokens only
8. No raw HTML (`<button>`, `<input>`) — use component library
9. All forms use react-hook-form + Zod validation
10. Functions max 50 lines, nesting max 3 levels

### Data Display (BLOCKING — most commonly missed)
11. ALL pagination is backend-only — never `.filter()/.slice()/.sort()` on frontend arrays
12. ALL search/filter/sort/pagination synced to URL params via `useSearchParams`
13. Every list page uses the registered DataTable component — never inline tables
14. Every API response has loading skeleton, error state, and empty state

### Security (BLOCKING)
15. Never hardcode secrets — environment variables only
16. Validate ALL input at API boundary
17. Never expose stack traces in error responses

### Git
18. Feature branches: `feat/mN-[name]` from milestone branch
19. Commit format: `type(scope): description`

### After Every Session
20. Update `AI_DOCS/memory/task.md` — mark completed `[x]`, in-progress `[/]`
21. Update `AI_DOCS/memory/project-context.md` if state changed
22. Log decisions in `AI_DOCS/memory/decision-log.md`
