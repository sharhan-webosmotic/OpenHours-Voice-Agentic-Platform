# Project Context — CLAUDE.md Generator

> **Purpose**: Generate and maintain `CLAUDE.md` at the project root.
> **Why it exists**: `AI_DOCS/memory/` files are the source of truth, but Claude Code doesn't read them automatically. CLAUDE.md is the **bridge** — a single file Claude Code reads at session start to instantly restore full project context.
> **Output**: `CLAUDE.md` (project root)

> **Renamed in v3.1.0** — was `/claude-md`. Router resolves the old name via `docs/skill-deprecations.md` for one minor version.

---

## Template Reference

The canonical CLAUDE.md template lives at `templates/CLAUDE-template.md` — full structure with all sections. The inline template below is a summary; the template file is the authoritative source.

**When generating, always:** (1) stamp the top `<!-- adf-version: X.Y.Z -->` marker with the value in `.claude/.adf-version` (this is what `upgrade.sh`'s staleness check greps for because omitting it makes the file perpetually re-flag as stale); (2) keep the `## Framework Operating Rules` block (single-interface `/do`, framework routing, compaction recovery) so regenerating never drops the governance that a project needs at session start. (3) never write `@` imports of rule files or AI_DOCS files: an import loads the whole file into every session and every subagent. Point at them for on-demand reading instead (cost policy, v4.28.0).

## Generation Rules

1. **Never guess** — only populate fields from actual memory files. Use `[UNKNOWN — read project-context.md]` if a field is missing.
2. **Always include the "When starting a session" instructions** — this is the most important section for Claude Code.
3. **Keep it scannable** — Claude Code reads this in the first few seconds of a session. No walls of text.
4. **Date stamp it** — always write `Last updated: YYYY-MM-DD HH:MM` so staleness is visible.
5. **Gate status is binary** — PENDING, PASSED, or FAILED. No vague states.
6. **Git state is current** — always reflect the actual git state, not the planned state.

## Sync Protocol (Workflow D — Session Restore)

When a session resumes on an existing project:

1. Read `CLAUDE.md` (if exists) — get snapshot of last known state
2. Read `AI_DOCS/memory/project-context.md` — compare with CLAUDE.md
3. If they differ → **update CLAUDE.md** with current state
4. Announce to user: "CLAUDE.md synced — project state restored"

**If CLAUDE.md doesn't exist but AI_DOCS/memory/ does:**

→ Run full generation from memory files. CLAUDE.md was never created or was deleted.

**If neither CLAUDE.md nor AI_DOCS/memory/ exists:**

→ New project. Run `session-management` Workflow A, then generate CLAUDE.md.

After EVERY skill completion, if any of these changed, update CLAUDE.md:

- Tech stack confirmed

## Troubleshooting

### Error: `CLAUDE.md` exists but is empty

**Cause:** previous generation was interrupted.

**Solution:** Delete `CLAUDE.md` and run `/project-context` again to regenerate from memory files.

### Error: Memory files missing

**Cause:** project was not initialized via `/session-management`.

**Solution:** Run `/session-management` first, then `/project-context`.

### Error: CLAUDE.md conflicts with AI_DOCS/memory/

**Cause:** CLAUDE.md drifted from the source of truth.

**Solution:** Trust `AI_DOCS/memory/` — regenerate CLAUDE.md from memory, don't edit CLAUDE.md manually.

## Rules

1. CLAUDE.md lives at **project root** — never in `AI_DOCS/` or `.claude/skills/`
2. CLAUDE.md is **read-only for humans** — generated by this skill only
3. CLAUDE.md is **not the source of truth** — `AI_DOCS/memory/` is. CLAUDE.md is a summary.
4. If CLAUDE.md conflicts with `AI_DOCS/memory/` → trust `AI_DOCS/memory/`
5. Regenerate CLAUDE.md at the start of every milestone
